## Git 远程推送链路打通（关键环境教训）

- 完成远程仓库推送：github.com/xulinchao/ai-manju，main 分支已与本地一致（241a55b）。
- **根因链（三层，逐层排除后定位）**：
  1. 系统级 `credential.helper=manager`（Windows 凭据管理器）排在所有助手之前，非交互会话中弹不出窗口 → `fatal: could not read Username ... terminal prompts disabled` → exit 128。
  2. `git config --local credential.helper ""` **无法写入空值**（git config 会丢弃），重置标记必须**直接编辑 .git/config** 手写 `helper =` 空行。
  3. 即使改用 `!` 前缀 shell 助手（gh auth git-credential），在本机 shim 环境下 git 经 `sh -c` 调用助手后**拿不到返回的凭据**（trace 到 `run_command: ... gh.exe auth git-credential get` 后即止，无后续 HTTP 动作）；手动在 sh 下执行同一命令却正常。**结论：本机 git 不要依赖 `!` 前缀外部助手。**
- **可用方案（已落地）**：`git config --local credential.helper store` + 写入 `%USERPROFILE%\.git-credentials`（明文，格式 `https://用户名:令牌@github.com`）。store 是 git 自带二进制、直接调用不经 shell，`git credential fill` 验证通过。
- **⚠ 最终结论（修正上一条）**：`store` 助手在 git 派生时同样失效（trace 到 `run_command: 'git credential-store get'` 即断，无后续动作）——**本环境下 git 的任何凭据助手都不可用**，只有「凭据直接写在 remote URL 里」能工作。已执行：`git remote set-url origin https://x-access-token:<token>@github.com/xulinchao/ai-manju.git`，并删除 `~/.git-credentials` 与 `.git/config` 的 credential 段，令牌只存 `.git/config` 一处。此后普通 `git push` 即可，exit 0 已验证（7a04d9a）。
- **临时可用方案**：令牌 URL 直推 `git push https://x-access-token:$tok@github.com/用户/仓库.git main`（经 `sh.exe -c` 执行，避免 PowerShell 参数篡改）。
- **PowerShell 输出捕获教训（深化）**：`Start-Process -RedirectStandardOutput/-PassThru` 在本环境返回空 ExitCode 且输出文件为空；`*> file` 写的是 UTF-16（Reading 会当二进制拒绝），需 `Get-Content -Encoding Unicode` 转换；**唯一可靠的取错方式**是 `GIT_TRACE=I:/绝对/路径/trace.log`（注意 GIT_TRACE 值不含斜杠时只写 stderr，不落文件）。
- 副作用清理：`C:\Users\xulinchao\bin\gh.exe`（为规避空格路径而复制）已不再需要；`_backups/trace*.log` 保留作证据。
