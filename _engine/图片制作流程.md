# 本地图片制作流程

当前规范适用于 image_pipeline_version=2 的项目。旧故事不自动迁移。

## 工作方式

用户提供故事和方向 → 画风候选 → 用户选定 → 角色/场景/道具主参考 → 用户审核 → 必要角度与机位派生 → 分镜图片 → 用户审核 → 视频。

所有图片处理走本地 ComfyUI。本轮不安装模型，不执行视频、声音与成片生产。CSV 写内容，assets.json 写真实输出与审核状态，不把“有文件”当成审核通过。

## 文件职责

- project.json：画幅、模型引用、image_pipeline_version、candidate_limit、art_direction、可选 review_style_asset。
- asset_jobs.csv：画风、角色、场景、道具和变体的生成说明。
- shots.csv：镜头事实和生成输入，唯一镜头内容源。
- assets.json：候选版本、审核意见、当前选定、真实输入文件与哈希、种子、实际工作流。
- candidates/<编号>/vNNN.png：永久候选。状态改变不改图片；--force 只新增候选。
- 分镜.html：从当前记录生成，用户在对话中按编号@版本反馈。

## 图片路径

image_route=t2i 用于探索；edit 接 1—3 张已审核图片；masked 使用底图与遮罩生成并合成局部；crop 精确裁切原图；faceswap 是独立可选任务。

references 为 JSON 数组，例如：[{"asset":"ROOM-A@v001","purpose":"机位和空间"},{"asset":"CHAR@v001","purpose":"身份与服装"}]。不写版本时解析当前选定版本，实际版本会记入候选；写明版本但已不再选定时拒绝继续。

edit_source 引用已审核资产，作为第一张图。references 接在它之后，合计不超过三张。masked 必须有 edit_source 与 mask；底图限 RGB PNG，避免透明度和位深被隐式转换；遮罩是项目内 PNG，红通道白色修改、黑色保护、灰色混合，尺寸必须与底图一致。遮罩应包含相关阴影和遮挡。生成结果先缩放匹配底图再合成，下载后机器核对黑色保护区域像素；不承诺修改区域内部的几何正确。

crop 为 JSON：{"x":0,"y":0,"width":256,"height":256}，与 edit_source 配合使用；无需重绘。

faceswap 需要 edit_source 身体底图和一张 references 脸部图，调用已有双图换脸工作流。创建独立修图编号，结果仍待审核，不覆盖原图。

requires 用分号分隔审核前置，如 LOOK;CHAR;ROOM-A。review_style_asset=LOOK 时，非画风任务自动等待 LOOK，并使用被选定候选的画风快照。画风图片只承担审美判断，不自动成为合格角色或场景。

scene_state 仅写当前镜头的光线、服装、道具变化。角色身份与状态变体分开编号；例如 POT-CLOSED、POT-OPEN，共享身份依据。

## 命令

```powershell
python _engine/gen_images.py --project "003-一致性验证" --assets --only LOOK --dry-run
python _engine/gen_images.py --project "003-一致性验证" --assets --only LOOK
python _engine/gen_images.py --project "003-一致性验证" --assets --only LOOK --style woodcut_clean --force
python _engine/assets.py --project "003-一致性验证" --list
# 仅在用户明确选定后执行，note 写用户实际意见：
python _engine/assets.py --project "003-一致性验证" --asset LOOK --version v001 --status approved --note "用户选定此画风"
python _engine/gen_images.py --project "003-一致性验证" --assets --only CHAR,ROOM-A,POT
node _engine/gen_html.js --project "003-一致性验证"
python _engine/qc.py --project "003-一致性验证" --stage preflight
python _engine/qc.py --project "003-一致性验证" --stage approved
python _engine/qc.py --project "003-一致性验证" --stage media --strict
```

--only 可指定镜头 S01 或具体 S01.first。first_prompt 产生 <shot>.first；非空 last_prompt 产生 <shot>.last，后者等待首图审核并通过 edit 派生。first_image/last_image 是兼容命名提示，新流程实际媒体路径由 assets.json 的选定版本解析，避免维护会被覆盖的副本。

画风对比可用 style_compare.py --project ... --shot S01 --styles picturebook_clean,woodcut_clean；不修改 project.json。

## 失败与返工

预检不创建目录、不访问生成接口、不回填视频。缺图、参考未审核或已失效、未知路径均停止该任务，不回退文生图。每个编号最多 candidate_limit 次尝试，失败也计数；达到上限先复盘，不无限加次数。已有候选默认跳过，有修改需求显式 --force 新增版本。

每次出图的实际工作流另存 .workflow.json。服务端任务超时或下载失败可用 --recover 编号@版本，按原 prompt_id 恢复，不重复提交。网络错误会报告，未自动取消服务端任务。

参考换版、撤回审核或输入文件被修改时，下游显示需复核并阻止继续；根据当前参考重新生成，不直接把旧候选解除失效。当前按顺序运行 CLI，不同时运行多个生产进程。

## 审核标准

画风检查线条、色板、材质；角色检查脸型、发型、衣服和比例；场景检查门窗、家具、机位和遮挡；分镜检查身份、空间、道具状态与叙事是否一致。局部像素检查只是技术检查，边缘自然度仍需人工确认。

## 视频边界

first 是单首图视频，reference 是双参考图视频。旧 firstlast 名称只为兼容读取：现有 R2V 节点没有结束帧时间绑定；非预检执行需要 --ack-reference-semantics 明确确认，或将新项目模式写为 reference。新项目仅使用已审核分镜。--chain 不自动投产视频。

## 运行环境与验证

Python 3.10+，Pillow（本机已安装，用于尺寸和像素核验），Node（看板入口），本地 ComfyUI。视频检查需要 ffprobe；缺失时报告未验证。
